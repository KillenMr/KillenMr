## 核心处理流程

1. 创建项目，完成关键词研究与聚类。
2. 生成内容大纲和文章，记录各阶段结果及调用费用。
3. 根据质量评分决定是否限次改写，并对改写结果重新评分。
4. 查询任务状态，将内容导出或发布至 CMS。

## 工程重点

- **9 个 MCP 工具：** 基于 MCP SDK 封装项目创建、关键词研究与聚类、内容生成、状态查询及导出等能力；使用 Zod 定义输入约束，统一成功和错误结果格式。
- **质量反馈：** 在多阶段生成流程中加入质量阈值、改写次数上限和复评，保存阶段结果与费用，支持自动执行。
- **持久化任务：** 基于 PostgreSQL 保存任务，通过状态条件更新领取任务，结合幂等键、重试上限和超时回收支持失败后的重新调度。
- **多租户交付：** 结合工作区成员角色与 RLS 控制访问，集成 Stripe 订阅、套餐配额和 Strapi 内容发布。

## 实践中的取舍

MCP 工具提供明确的输入、输出和错误契约；内容工作流负责阶段衔接与质量反馈；持久化任务保存执行进度和失败状态。将这些职责分别实现，便于独立排查工具调用、生成质量和任务执行问题。
